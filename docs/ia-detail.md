## 一、页面结构：左文右图 + 手风琴滚动联动

```
┌────────────────────────┬────────────────────────────────────┐
│  左栏（固定，文字）       │  右栏（大面积，可滑动的图 / 原型 / 渲染） │
│                         │                                    │
│  项目名 · 一句话副标题    │   [图1] → [图2] → [图3] → [图4] …    │
│  元数据行：类型·角色·年份  │   细节 / 原型 / 最终渲染             │
│  ─────────────────      │                                    │
│  ① 用户背景        ▾     │   ← 右侧滑到哪一段的图，              │
│  ② 关键决策与取舍   +     │      左侧自动展开对应那一段文字，       │
│  ③ 过程            +     │      其余段落自动折叠。               │
│  ④ 最终呈现        +     │                                    │
│  ⑤ 反思            +     │                                    │
│  ─────────────────      │                                    │
│  ← 上一项目 / 下一项目 →  │                                    │
└────────────────────────┴────────────────────────────────────┘
```

- **手风琴（Accordion）**：左栏五段，同一时刻只展开一段，其余折叠（`▾` 展开 / `+` 折叠）。
- **滚动联动（scroll-linked）**：不是靠点击展开，而是**右侧图片滑动位置驱动左侧展开哪一段**。右侧滑到"最终渲染"的图，左侧自动切成"④ 最终呈现"，其余收起。
- **元数据行**（学 BOC 的 `AUTOMOTIVE · BOOST · 2025` / Henning 的 meta 块）：`类型 · 角色 · 年份`，放在标题下方，扫读用。
- **进入方式**：从首页作品行单击图片进入本页；底部有上一/下一项目。

## 二、五段内容骨架（每个项目通用）

| 段 | 左栏文字（写什么，务必短） | 右栏配图（放什么） |
|---|---|---|
| **① 用户背景** | 一个真实的缺口 / 痛点，用户或场景说话。为什么这事值得做。 | 场景图 / 调研画面 / 问题的视觉化 |
| **② 关键决策与取舍** | **本页最重要**。为什么这么做、放弃了什么、在什么之间权衡。 | 概念图 / 方案对比 / 关键机制示意 |
| **③ 过程** | 怎么一步步做出来的：方法、技术、迭代。 | 流程图 / 原型 / 技术链路 / 模型制作 |
| **④ 最终呈现** | 做出了什么：最终形态与效果。 | 最终渲染 / 成品 UI / demo |
| **⑤ 反思** | 结果如何、如果重来会改什么。展示判断力。 | 收尾图 / 使用场景 / 一张有分量的图 |

> 扫读层已在首页（一句话决策钩子 + 角色 + 元数据）。本页是**深读层**：给愿意点进来的招聘者和导师看完整论证。
> 决策要靠前——② 紧跟 ① 之后，别让人滑到最后才看到你的判断。

## 三、Orbit 样例（把骨架填一遍，看具体长相）

**标题**：Orbit 时环 — 把一趟旅程重新收拢成一个完整的形状
**元数据行**：App + 硬件系统 · UX / 交互 · 系统设计 · Solo · 2025

| 段 | 左栏文字要点（草稿，非最终文案） | 右栏配图（用现有素材） |
|---|---|---|
| **① 用户背景** | 旅程结束后，体验是散的——照片在相册、步数在手环、轨迹在地图、情绪在脑海。碎片难整理，也无法在情感上重构为一次完整旅程。 | `orbit_recall`（回忆总览）/ 散落素材拼贴 |
| **② 关键决策与取舍** | 决定把"一段旅程"抽象成**一枚环形时钟（时环）**，每个景点是环上一个节点。**取舍**：放弃传统相册/时间线的堆叠式浏览，赌"可视化 + 可分享"的统计页更能唤起情感——代价是用户要接受一种全新的浏览隐喻。 | `orbit_home`（时环主界面）/ 概念示意 |
| **③ 过程** | 基于 5E 体验模型：记录一键开始 → 时环随旅程"生长" → 旅程结束闭合成回忆。可从一整年缩放到某一天。并延伸出 Pebble（记录硬件）与 Bubble Light（回放摆件），形成系统。 | `orbit_create` / `orbit_record` / `orbit_place`（流程界面） |
| **④ 最终呈现** | 成品：一个可交互、可分享的旅行记忆系统 + 一套完整设计规范（思源黑体、六色时环光谱、几何/光晕）。 | `orbit_memories`（城市环）/ `orbit_tokens`（设计规范） |
| **⑤ 反思** | 时环隐喻降低了"整理"的负担，但也带来学习成本；若重做会更早验证"环形浏览"是否直觉。系统三件套的联动逻辑还可更清晰。 | 一张有分量的收尾图 |

> 右侧滑动顺序 = 上表从上到下；左侧手风琴随之展开对应段落。

## 四、三个项目的差异化（同一格式，不同侧重）

- **Orbit**：② 决策段突出"系统级抽象"（把旅程变成时环 + 三件套）。
- **EchoCourt**：③ 过程段突出技术链路（捕捉→比对→反馈：MediaPipe / DTW / ESP32），② 突出"技术隐形"与"模块化而非重做拍子"的取舍。
- **Serava**：① 背景段突出调研数据（61 问卷 / 6 访谈），② 突出"让 AI 有情感而非诡异"的取舍，③ 突出形象生成状态机。

## 五、护栏（Phase 4 实现时记得）

- **移动端退化**：窄屏无法左右分栏 → 退成上下堆叠（图 + 其下文字），手风琴仍可点击展开。
- **联动逻辑**：滚动位置 ↔ 手风琴段落的同步，是本页最复杂的一块，交给 Claude Code 实现并测试。
- **可访问性**：手风琴用语义化标签、键盘可展开；尊重 prefers-reduced-motion。
- **性能**：右侧大图懒加载，别一次性全载。
